## 用户反馈与本轮范围

用户已在项目管理处关闭旧 opencode 项目，但左侧没有同步消失，要求检查是否需要修改逻辑。本轮核对现有源码并提出最小修复方案，尚未获得具体方案实施授权；不重启应用或后台，不删除项目数据或会话。

## 源码发现

- `packages/app/src/runtime/server/registry.tsx` 的 `close(directory)` 从本地已打开列表移除项目，并在 `recentlyClosed` 中记录关闭状态。
- `packages/app/src/shell/project-sidebar.tsx` 的 `projects` memo 先读取相同的已打开列表，但随后在当前路由/草稿/Home selection 指向的目录不在列表时，额外补一个项目；该分支未检查 `ctx().projects.closed()`。
- 因而已关闭项目如果仍被当前选择或旧标签页路径引用，可以被侧栏自己的兜底分支重新显示，并不需要后台重新打开它。这是源码中可明确导致反馈现象的路径；本轮未完成真实桌面复现，不据此声称已排除所有运行时因素。
- `registry.tsx` 的关闭移除使用 `project.worktree !== directory` 原始字符串比较，而关闭记录和侧栏匹配使用 `pathKey`；Windows 同一路径的分隔符或规范化差异可能让移除漏掉已有项。需统一为现有路径比较规则，而非扩大成新的项目标识体系。

## 建议的最小修复

1. 侧栏继续使用共享已打开项目列表；只有当前目录不是显式关闭的项目时，才允许补充当前项目兜底。
2. 项目移除使用 `pathKey` 比较，保持与关闭记录及侧栏匹配一致。
3. 保留显式重新打开行为：用户重新打开项目时，清除关闭标记，项目正常回到侧栏；关闭入口不删除会话、不改变会话执行或当前标签页。
4. 在现有首页/项目导航回归测试中保护关闭后侧栏消失、旧选择不重新补回、显式重新打开恢复，以及 Windows 路径等价情况。测试落地前读取对应测试技能，避免重复契约覆盖。
5. 实施后运行相关验证，并按现有 A/B 流程暂存更新；不强制退出或重启当前应用/后台。不顺带实施或恢复 2.2 对齐计划。
